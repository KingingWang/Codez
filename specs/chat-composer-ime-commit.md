# 聊天输入框 IME 提交

## 产品规则与边界

- 桌面和 Web 的聊天正文使用同一个 Lexical 编辑器。编辑器是组合输入文本及选区的唯一所有者；`onChange` 只把已观察到的正文投影给草稿，`onSubmit` 只处理真正的发送意图。
- 输入法用 Enter 确认候选词或提交原始英文时，不触发发送、不插入额外换行、不丢失或重复正文。组合结束后的下一次普通 Enter 才按现有发送/换行快捷键规则执行。
- 空编辑器和已有正文的编辑器遵循同一规则。中文候选确认、英文原文提交、取消组合后仍为空的情况均不得留下临时组合字符。
- 不更改会话协议、持久化格式或远程交付语义；桌面和手机 Web 均使用编辑器既有的 `onChange` / `onSubmit` 接口。

## 事件顺序与修复依据

讯飞拼音在 Chromium 上提交原始英文的顺序可能是：

```text
IME 组合输入 → Enter(isComposing=true)
             → insertCompositionText("") / 删除临时 DOM 文本
             → compositionend(data="")
             → insertText("hello") → 编辑器正文 / onChange
```

空输入框会为组合输入创建临时文本节点。旧版 Lexical 在空 `compositionend` 时安排延迟删除该节点，即使随后 `insertText` 已把真实文本写入，也会删除它。升级编辑器依赖到包含上游 #8701 修复的 Lexical 0.46.0：清空旧组合态，并只删除仍为空的节点；不在 React 层复制组合态或用超时恢复草稿。

## 验收场景

1. 空草稿下用讯飞拼音输入 `hello` 并按 Enter：延迟清理结束后正文为 `hello`，发送次数为零；后续再次按 Enter 才发送一次。
2. 已有 `prefix` 的草稿中用同一输入法提交 `hello`：正文为 `prefixhello`，不重复、不发送。
3. 组合输入真正取消且未产生后续 `insertText`：临时节点被移除，正文仍为空。
4. macOS 系统中文输入法确认中文候选词，以及普通英文键入和非组合态 Enter：维持既有行为。

自动化回归在 Chromium 中模拟上述组合事件顺序并等待延迟清理；真实讯飞与系统输入法的桌面手测用于补充浏览器无法完全仿真的平台输入事件。
