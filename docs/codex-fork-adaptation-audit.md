# Codex fork adaptation audit (2026-10-02)

This is a bounded audit of the checked-out Codez fork against its native Codex
contract. It does not certify every platform or interaction. The adjacent
`/root/workspace/codex` checkout is reference material, not an input to builds.

## Ownership and event order

```text
Help menu (display only)
  → DesktopCommandIds.CheckForUpdates
  → Main updater (feed, download, restart/install authority)
  → update-state event
  → Help menu (derived status label and disabled state)
```

The Main-side handler already checks packaged runtime and dispatches
`update-downloaded` to the existing install path. The renderer does not store
another download queue or invent a second installer.

## Suggested acceptance expansion

1. On a host with free inotify capacity and the exact pinned Node version,
   launch a fresh isolated desktop profile; traverse workspace, conversation,
   Help, Settings, files, Git and terminal from both mouse and keyboard. Log the
   control's before/after state and any native command rather than counting a
   rendered control as a working action.
2. Repeat native model selection, queue/guide/interrupt, attachments, approvals,
   history and reconnect with owned test-only loopback accounts and file fixtures;
   assert workspace identity isolation and desktop-continuous versus
   web-remote-replayable recovery independently.
3. In disposable packaged Linux/macOS/Windows environments, verify update-feed
   discovery and Help menu state. Testing download/install requires a controlled
   test release and explicit authorization; never modify a real user's install.
4. Re-run the full matrix when a new native Codex release is selected, and
   preserve the exact executable digest, schema version, screenshots, command
   results and unresolved coverage in the acceptance report.
